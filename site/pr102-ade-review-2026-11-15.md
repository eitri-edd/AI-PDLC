- **Concepts — Git worktrees**: [Git's worktree manual](https://git-scm.com/docs/git-worktree) describes management of multiple working trees attached to one repository. It supports separate working copies, not a security boundary; the warning about what a same-identity process may access is an inference from normal permissions, not a Git sandbox guarantee. No security isolation test was performed.
- **Agents — Claude worktrees**: [Anthropic's worktree documentation](https://code.claude.com/docs/en/worktrees) describes separate working directories for parallel sessions and explicitly says untracked `.env` files are absent from a fresh checkout; `.worktreeinclude` can copy matching gitignored files. It also says its background worktree checks do not track the files written by shell commands. Some saved Bash approvals apply across the main checkout and worktrees; on Windows and where Claude Code does not use the repository root, the documented rule stays in the worktree. These are product-specific statements, not a guarantee about other tools.
- **Concepts and Agents — Claude sandbox**: [Anthropic's sandbox documentation](https://code.claude.com/docs/en/sandboxing) describes an OS-enforced shell-command boundary, off by default, on macOS, Linux and WSL2; native Windows commands are unsandboxed. File tools, hooks and MCP servers run outside it. Default sandboxed reads include credential files, and network access is mediated by a host-checking proxy; retry outside the sandbox depends on configuration. These facts support choosing and testing controls, not presuming isolation or proving any ADE's controls.
